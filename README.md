# Состав на игру — генератор постера (HC Dinamo Minsk)

Веб-приложение: редактор состава + векторный постер (SVG) с экспортом в PNG.
Без зависимостей и сборки. Опубликовано на GitHub Pages: вход по логину и паролю,
у каждого логина своя база сохранений.

## Вход: логин и пароль

Сайт статический, сервера нет, поэтому защита целиком на шифровании:

- `app.html` шифруется один раз общим мастер-ключом сайта (`master.key`, в репозиторий
  не попадает) и встраивается в `index.html` — без ключа приложение из исходников
  страницы не извлечь (PBKDF2-SHA256 310 000 итераций + AES-256-GCM).
- Мастер-ключ завёрнут паролем каждого логина отдельно (`users.json`, тоже не в
  репозитории). Логин + пароль разворачивают ключ, и тот уже расшифровывает приложение
  в браузере (WebCrypto). Пароль никуда не отправляется.
- Неверный логин и неверный пароль дают одинаковую ошибку и одинаковое время ответа —
  по форме входа нельзя понять, какие логины существуют.
- После входа в `sessionStorage` вкладки лежат ключи (не пароль): перезагрузка не просит
  пароль снова, закрытие вкладки — просит. Кнопка «выйти» в приложении сбрасывает сессию.
- Пароль подбирается оффлайн прямо по `index.html`, поэтому берите длинный (от 12 знаков):
  короткий пароль ломается за секунды вместе с содержимым приложения.

## Логины: добавить, изменить, убрать

```
node add_user.mjs dima --name "Дмитрий"    # пароль спросит без эха
node add_user.mjs vera --inherit           # и перенять базу этого браузера
node add_user.mjs old --remove             # убрать логин
node add_user.mjs --list                   # кто уже есть
node build_gate.mjs                        # пересобрать index.html, затем git push
```

Сразу пачка логинов со случайными паролями (пароли уходят в файл, не в консоль):

```
node add_user.mjs --generate 10 --prefix trener    # trener1 … trener10
node build_gate.mjs && git push
```

Пароли печатаются в `logins.txt` (в `.gitignore`, chmod 600) строками `логин<tab>пароль`:
отдайте каждому его строку и удалите файл — восстановить пароль потом нельзя, в `users.json`
лежит только мастер-ключ, завёрнутый паролем (забытый пароль = завести логин заново).
Пароли генерируются 14 знаков без похожих на слух и на вид символов (0/O, 1/l/I).

Для скриптов: `LP_PASSWORD='...' node add_user.mjs dima` (пароль останется в истории shell).

Пароли в файлы не пишутся — в `users.json` лежит только мастер-ключ, завёрнутый ключом
от пароля. `master.key` и `users.json` внесены в `.gitignore`: не теряйте их — без
`master.key` не войти ни одним логином, без `users.json` логины придётся заводить заново.
Для пересборки `index.html` пароли больше не нужны.

## База сохранений у каждого логина своя

- Состав, автосейв, «состав от предыдущей игры» и логотипы команд лежат в localStorage
  браузера под ключом логина: `lp:<логин>:saves`, `lp:<логин>:auto`, `lp:<логин>:prev`,
  `lp:<логин>:logos`.
- Каждая запись зашифрована ключом, который выводится из пароля этого логина (PBKDF2 с
  отдельной солью). Открытого текста в браузере нет, и ключом другого логина запись не
  читается — проверено тестом.
- Два логина в одном браузере друг друга не видят: у каждого свой состав и свои логотипы.
- Логин с `--inherit` при первом входе забирает базу прежней версии (общие ключи
  `dinamo-lineups*`) и переносит её в своё зашифрованное хранилище — сохранения не теряются.
- Базы привязаны к браузеру и устройству: на телефоне или другом компьютере у того же
  логина будет своя пустая база. Общая база между устройствами статическим сайтом
  невозможна — для этого нужен сервер (например, Supabase/Firebase).

## Пересборка после правок приложения

1. Отредактируйте `app.html` (это и есть приложение; оно в `.gitignore` и никогда не
   публикуется в открытом виде).
2. Соберите публичный `index.html`: `node build_gate.mjs`.
3. Закоммитьте и запушьте — GitHub Pages обновится сам.

## Локальный запуск без входа

Откройте `app.html` в браузере (Safari или Chrome) — приложение работает в локальном
режиме: баз без шифрования, ключи `lp:local:*`, в строке слева внизу это подписано.

## Использование

- Сверху слева — три вкладки постера, у каждой свои номера, дата и имя файла:
  - «Игра» — состав на игру: 4 звена, 13-й нападающий, 3 пары, 7-й и 8-й защитники, вратари.
  - «Тренировка» — тренировочная группа (неиграющий состав): по 3 ряда нападающих
    и защитников плюс вратари, без 13-го и 7-го.
  - «PK» — сочетания в меньшинстве: 4 двойки нападающих, 3 двойки
    защитников и один вратарь.
- Слева — редактор: дата матча, формат, разрешение и номера всех звеньев, пар и вратарей.
- «Команда» — пресет клуба КХЛ либо «Своя команда»: от неё считаются подложка, майки и логотип (раздел ниже).
- «Формат постера» — 3:4, 2:3, 9:16, 1:1, 4:3, 16:9.
- «Разрешение» — длинная сторона PNG: 1600, 2400 (по умолчанию), 3200 или 4000 px;
  вторая сторона считается из выбранного формата.
- Номера вводятся без фамилий. Пустое поле убирает свитер из состава — так можно
  оставить 12 нападающих без 13-го, 6 защитников без 7-го и 8-го или двух вратарей без третьего.
- «Скачать PNG» — файл `dinamo-lineup-…`, `dinamo-practice-…` или
  `dinamo-pk-ДД-ММ-ГГГГ-формат.png` сохраняется в Загрузки.
- «Сбросить к дефолту» — возврат дефолта активной вкладки: игра (9-17-23 / 11-14-77 /
  19-22-88 / 21-63-94, 13-й — 71, пары 4-55 / 6-44 / 27-91, 7-й — 2, 8-й — пустой,
  вратари 30, 1 и третий — пустой),
  тренировка (10-16-29 / 58-81, защитники 3-5 / 8, вратарь 35),
  меньшинство (нападающие 19-22 / 21-63 / 11-14 / 9-17, защитники 27-91 / 4-2 / 6-44, вратарь 30).
- «Состав от предыдущей игры» — подставить номера прошлой игры (подробнее в разделе ниже).

## Команда: дизайн собирается от клуба

Весь вид постера считается из цвета команды, а цвет команды — из её логотипа.

- «Команда» — пресеты клубов КХЛ (Динамо Минск, Динамо Москва, ЦСКА, СКА, Ак Барс,
  Авангард, Автомобилист, Адмирал, Амур, Барыс, Лада, Локомотив, Металлург, Нефтехимик,
  Салават Юлаев, Северсталь, Сочи, Торпедо, Спартак, Сибирь, Шанхай Драконы, Зубр)
  либо «Своя команда» с любыми цветами.
- Из акцента команды считаются: акцент линий, подписей и свечения, три комплекта маек
  (белая выездная, тёмная домашняя, цветная — в цвет команды) и пять оттенков подложки
  (клубная с логотипом, тёмная в цвет команды, цветная, светлая, без фона).
- «Цвет команды» — пикер для поправки акцента; «Как у логотипа» возвращает цвет,
  снятый с логотипа клуба.
- Логотипы клубов лежат в папке `logos/` рядом с сайтом — по файлу на клуб. Свой файл,
  загруженный в слот «Мы», важнее клубного логотипа; «Убрать» возвращает клубный.
- Шапка по-прежнему с двумя слотами: «Мы» (по умолчанию — логотип выбранной команды)
  и «Соперник» (только ваш файл).
- Имя PNG начинается с кода команды: `cska-lineup-…`, `ska-lineup-…`; у Динамо Минска
  как раньше — `dinamo-lineup-…`.
- Если страница открыта локально как файл (`file://`), браузер не даёт подтянуть логотипы
  из `logos/` — в этом случае работают только свои загруженные файлы.

## Состав от предыдущей игры

Всё, что вы вводите — номера, роли K/A, дату, формат, подложку, цвет маек и логотипы команд, —
приложение сохраняет само (localStorage браузера, у каждого логина своя база, отдельно по каждой вкладке). Кнопка
«Сохранить состав» нужна только для именованных записей в списке «Сохранённые».

- Перезагрузка страницы или возврат на сайт в тот же день — состав, дата и вид постера
  восстанавливаются целиком.
- Если сайт открыт в другой день, номера и роли подставляются из состава прошлого дня,
  а дата автоматически становится сегодняшней; под кнопкой видно, из какого дня взяты номера.
- «Состав от предыдущей игры» возвращает последний состав, который вы скачали кнопкой
  «Скачать PNG» (если афиша не скачивалась — состав прошлого дня). Дата не меняется: это
  новая игра. Кнопка выручает после «Сбросить к дефолту» и после экспериментов с номерами.
- Данные лежат только в этом браузере, у каждого логина зашифрованы его ключом и никуда не отправляются.

## Как устроен рендер

Постер рисуется как inline SVG в клубных цветах (голубой #45B7E8, чёрный, белый):
тёмный фон, логотип «Динамо» по центру с лёгким размытием, белые свитеры выездной
формы — голубой воротник, голубые полосы на рукавах, тёмный номер с голубым контуром,
раглан-швы и сетчатая текстура. Все свитеры одного размера в пределах постера.
Заголовок зависит от вкладки: СОСТАВ НА ИГРУ / GAME LINEUP,
ТРЕНИРОВОЧНАЯ ГРУППА / PRACTICE GROUP либо МЕНЬШИНСТВО / PENALTY KILL
(длинный заголовок автоматически сжимается по ширине постера). Названия блоков
выводятся на двух языках: НАПАДАЮЩИЕ / FORWARDS, ЗАЩИТНИКИ / DEFENSEMEN,
ВРАТАРИ / GOALTENDERS (на вкладке PK — ВРАТАРЬ / GOALTENDER).

Раскладка подстраивается под формат: приложение считает вариант в одну колонку
(нападающие → защитники → вратари) и в две (нападающие | защитники и вратари),
затем выбирает тот, где свитеры крупнее и постер заполнен по высоте. 13-й нападающий
выводится по центру под своими звеньями, 7-й и 8-й защитники — одной строкой под парами.

Готовый SVG растрируется через canvas в PNG выбранного разрешения — все цифры и
тексты остаются точными (вектор). PNG предрендерится в фоне при каждом изменении,
кнопка скачивает готовый файл синхронно.
